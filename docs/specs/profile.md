# Spec: profile（个人画像）

Status: 草案 2026-11-26，等批准（第 10 节有 3 个问题要作者定）　版本：V2
依据：`docs/ROADMAP.md` V2「`profile`」；`docs/specs/chat-reader.delta-paste.md`（文字来源，第 6 节第 2 条）；`docs/specs/llm-adapter.md`；2026-11-26 作者的决定（第 9 节）。

## 1. Objective

让 AI 读你在对话里说过的话，写一份「数字化的你」：放在 vault 的 `profile/` 目录，和原始材料分开。

一份画像有两层：

| 层 | 是什么 | 例子 |
|---|---|---|
| **你说过的** | 你自己明确说过的事实和看法，AI 只做归纳 | 「你在马来西亚读计算机」——有你说这句话的原话 |
| **推断** | 你没直接说过，但从很多对话里能看出来的规律，包括**你自己可能没意识到的** | 「你遇到新东西时，习惯先问『为什么』再问『怎么做』」——来自好几个不同对话 |

底线：

- **每条结论都带证据**：你的原话，加上它在哪个对话文件里，点一下就能打开核对。
- **证据有多少写多少，不设门槛**：一句话说得足够清楚，一条证据就够；同一天的对话也算。程序在每条结论旁写明证据来自几个对话、几天（这个数是程序数的，不是 AI 说的），你一眼能看出它是一次性的还是反复出现的。完全没有证据的写进「未解问题」，不硬编。
- **原话由程序核对**：AI 给出的每句「原话」，程序都会去你的对话里查，查不到就丢掉这条（防止 AI 编造你没说过的话）。
- **你说了算**：每条结论你都可以标「不像我」，下一版不会再这样写（第 7 节）。
- 需要你明确开启：不加 `--yes` 只显示要发多少字，什么都不发（docs/CONSTRAINTS.md）。

成功的样子：`eia profile run --yes` 跑完，`profile/` 里多一份带日期的画像。你读的时候，「你说过的」每条都对得上原话，「推断」里至少有几条让你觉得「确实是这样，但我以前没这么想过」。

## 2. 发什么给 AI

| 内容（来源见 chat-reader.delta-paste.md） | 发不发 |
|---|---|
| 「我写的」段 | 发 |
| 你在对话文件里写的笔记 | 发 |
| 贴回的 AI 回答（`ai`） | 发，标明「这是你贴回的 AI 回答」，每段最多 500 字；它代不代表你的看法，由 AI 结合你前后说的话判断 |
| 代码、报错、附件占位 | 不发：对画像没用 |
| AI 的回答、思考过程 | 不发 |
| 对话标题、日期、平台 | 发：帮 AI 理解上下文 |

- 只发给 `config.yaml` 里配置的文本模型（作者用 DeepSeek）。
- 范围：`--since` / `--until` 按消息时间选；不写时默认**最近 3 个月**。
- 作者的 test-vault 最近 3 个月：272 个对话，约 16 万字（我写的约 16.1 万字，贴回 AI 约 2 千字）。

## 3. 流程

```
第 1 步  本机准备（不联网）
         选出范围内的对话 → 按第 2 节整理材料 → 告诉你：多少个对话、多少字、发给哪个服务
         没有 --yes 就停在这里
              │
              ▼
第 2 步  逐个对话提取「观察」（发原文）
         AI 对每个对话（太短的几个拼一批，太长的切开）列出观察：
         属于哪一类、是「你说过的」还是「推断」、一句话内容、你的原话（可以几句）
         另外摘出能体现你看法、性格的原话，即使暂时归纳不出结论（给第 3 步保留原始材料）
         程序核对原话 → 查不到的丢掉
         结果存进 .eia/eia.db；对话没变就不重新发
              │
              ▼
第 3 步  按大类综合（发观察和摘出的原话，不发整段原文）
         每一类：把观察合成结论 → 每条结论引用观察的编号
         再跨类找「你可能没意识到的你」
         程序核对：证据编号存在，丢掉引用不存在编号的；数出每条结论的证据来自几个对话、几天
              │
              ▼
第 4 步  写文件：profile/<日期> 画像.md（新文件，旧版本不动）
```

- 第 2 步的结果按「对话内容 + 提示词版本 + 模型」缓存。以后把范围扩大到全部对话，已经分析过、内容没变的对话不再发。
- 第 3 步发的是第 2 步的观察（短句 + 原话），量比原文小得多。
- 任何一步出错（网络、模型输出格式不对）：已经完成的观察保留在缓存里，不写半成品画像；下次运行接着做。

## 4. 四个大类

| 大类 | 写什么 |
|---|---|
| 认知与学习 | 你学什么、怎么思考、怎么提问、常卡在哪里、学东西的习惯 |
| 兴趣与关注 | 长期关注的话题、变化（以后给兴趣分层 V2-3 用） |
| 价值观与信仰 | 你在意什么、怎么做取舍、信仰相关的想法 |
| 身份与经历 | 你自己说过的事实：在哪读书、做过什么、生活状况 |

另有一节 **「你可能没意识到的你」**：跨大类的推断（比如某种思维方式同时出现在学习和信仰的对话里）。

## 5. 画像文件

`profile/2026-11-26 画像.md`：

```markdown
---
id: profile-20261126-xxxxxx
type: profile
title: 2026-11-26 画像
created: 2026-11-26T10:00:00Z
status: inbox
schema: 1
period: 2026-08-26 ~ 2026-11-26
chats: 272
model: deepseek-v4-flash
---

> 根据 272 个对话（2026-08-26 ~ 2026-11-26）生成。「推断」是 AI 的判断，不是你说过的话。
> 觉得哪条不像你，把 `[ ]` 改成 `[x]`，可以在后面写原因。下次生成时会避开。

## 认知与学习

### 你说过的
- [ ] 不像我｜你在学 Java 和数据结构，正在准备期末考试 （把握：高｜1 个对话）
  - 「下周就考数据结构了，我链表还没搞懂」—— [[2026-11-02 MCQs on Data Structures]]

### 推断
- [ ] 不像我｜你习惯先弄懂「为什么」再记「怎么做」 （把握：中｜5 个对话、4 天）
  - 「为什么这里要用递归而不是循环」—— [[...]]
  - ……

### 未解问题
- 你更喜欢自己摸索还是有人带？材料里两种说法都有，不够下结论。

## 兴趣与关注
……

## 你可能没意识到的你
……
```

- 证据的原话截到 100 字以内；链接用 Obsidian 的 `[[文件名]]`，点开就是原对话。
- 每份画像是一个新文件，不覆盖旧版本。想重新生成就再跑一次；旧版本你可以留着对比，也可以自己删。
- 程序不改你已有的画像文件。你可以直接在里面加笔记。

## 6. 对 vault 格式的改动（批准后另写 `vault-schema.delta-profile.md`）

- 新增条目类型 `profile`，目录 `profile/`；`eia init` 创建这个目录。
- `profile` 条目额外字段：`period`（字符串）、`chats`（整数）、`model`（字符串），都是选填。
- `eia validate` 认识这个类型。`schema` 版本号不变（只是多一种类型，旧文件仍然合规）。

## 7. 「不像我」怎么起作用

- 下次运行时，程序读最新一份画像里你勾了 `[x]` 的条目（连同你写的原因），发给第 3 步，告诉 AI：「用户说这条不对」。
- AI 不再写出同样的结论，除非有新证据；即使有新证据，也要说明「你上次说不像你，但……」。
- 没勾的条目不算「你确认了」，只是没表态。

## 8. 命令

```
eia profile run [--vault <路径>] [--since 2026-08-26] [--until 2026-11-26] [--yes]
```

- 不加 `--yes`：只做第 1 步，列出要发多少对话、多少字、发给哪个服务、其中多少已有缓存不用再发。
- 加 `--yes`：做完全部 4 步，最后打印新画像的路径和每类结论条数、被丢掉的原话不符的观察条数。
- 只写 `profile/` 下的新文件和 `.eia/eia.db`；不碰其他文件。

## 9. 作者的决定（2026-11-26）

1. 发「我写的」段、笔记、贴回的 AI 回答；不发代码、报错、附件。贴回的 AI 回答可能正好代表自己的看法，要让 AI 看到并结合上下文判断。
2. 发给 DeepSeek（`config.yaml` 现有配置）。
3. 四个大类都做。目标是「数字化的我」，包括「我自己没想过、但确实是这样的我」。
4. 第一次只跑最近 3 个月，满意了再跑全部。
5. 推断不设证据数量门槛，同一天的对话也算；程序标出证据来自几个对话、几天，由作者自己判断。

## 10. 要作者定的问题

1. **「不像我」这一版就做吗？**
   - A（推荐）：做（第 7 节）。画像要越改越像你，这是最直接的办法。
   - B：先不做，只生成；以后再加。
2. **画像用什么语言写？**
   - A（推荐）：中文。证据的原话保持原样（英文、马来文就是原文）。
   - B：跟着材料的语言走。
3. **对话太短的跳过吗？**（最近 3 个月里，272 个对话中有 143 个你写的不到 100 字）
   - A（推荐）：不跳过。短对话也能说明你关注什么，而且几个拼成一批发，不多花请求。
   - B：跳过你写的不到 100 字的对话，省一半请求。

## 12. 已知局限

- 画像只看你在 AI 对话里说的话。你在对话里不聊的方面（比如家人、朋友），画像不会知道。
- 你的对话大多是学业，价值观、情感方面材料少，这几类可能大多是「未解问题」。见证稿、生活记录这类少量个人内容会很重要。
- AI 的推断可能错，所以单独标成「推断」并写明把握；原话程序能核对，推断只能靠你判断。
- 画像文件在 vault 里。如果你用 Git 把 vault 同步到公开仓库，画像会和对话一起被推上去。
