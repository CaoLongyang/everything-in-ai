# Delta Spec: profile V2（回复格式不对的批次跳过）

Status: 已批准 2026-11-26（作者：「失败的批次跳过」再重跑）　版本：V2
改动对象：`docs/specs/profile.md`（已批准）第 3 节「任何一步出错」

## 为什么改

2026-11-26 用本机模型 qwen3:8b 跑对比：第 2 步做到第 17/34 批时，模型的回复连续 3 次都不是合法的 JSON，整个运行停下，前 16 批之后的全部没做。一批坏掉就让整次运行作废，代价太大；DeepSeek 偶尔也可能遇到。

## 改动

- 第 2 步某一批的回复**重试几次都不合格式**（`LLMOutputError`）：跳过这一批里的对话，接着做后面的批次。
  - 一个长对话被切成几批时，只要有一批失败，整个对话就算这次没做成。
  - 跳过的对话**不写缓存**，下次运行会自动重试。
  - 画像文件开头写明「另有 N 个对话这次没分析成，没算进这份画像」；frontmatter 的 `chats` 只算真正分析了的对话。
  - 命令行最后列出这些对话的标题（最多 5 个）。
- **网络、key 这类错误**（`LLMCallError`、`LLMConfigError`）照旧停下：后面的批次多半也会失败，不该空跑完。已经做完的对话仍然留在缓存里。
- 第 3 步（汇总）出错照旧停下、不写画像。
