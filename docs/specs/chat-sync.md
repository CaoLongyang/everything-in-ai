# Spec: chat-sync（浏览器插件每天自动同步对话）

Status: 已批准 2026-11-27（实现时的调整见 ADR 0010 第 7–11 条）　版本：V2
依赖：`docs/specs/chat-import.md`（重复导入、标记块、保留用户内容）、`docs/specs/chat-import.delta-gemini.md` 第 4 节（消息变少时不更新）
实现决定：`docs/adr/0010-chat-sync-site-api.md`（为什么可以用网站的接口）
在总目标里的位置：第 1 层「采集」（`docs/ROADMAP.md` 开头）

## 1. 要解决的问题

现在要更新对话，得去网站点导出、等邮件、下载、再运行 `eia import`。所以 vault 里的对话总是落后几周，画像也跟着落后。

目标：**每天自动把 ChatGPT、Claude、Gemini 上的对话同步进 vault，你什么都不用做。**

- 不管你是在网页、电脑 App 还是手机 App 上聊的，都要同步得到（作者 2026-11-27：现在很多人用 App 而不是网页）。App 和网页是同一个账号，所以插件从网页那边取。
- 第一次同步全部对话；之后每天只同步更新过的。
- 每条消息要有准确的时间，和官方导出一样。

## 2. 怎么取数据：网站自己的接口

ChatGPT 和 Claude 的网页本身就是通过一些接口取你的对话列表和对话内容，返回的数据里有每条消息的时间、每个对话的更新时间，和官方导出包里的一样。插件在你**已经登录**的网页里请求同样的接口，就像网页自己刷新一样。

| 平台 | 对话列表 | 一个对话 | 消息时间 | 参考的开源代码（都是 MIT） |
|---|---|---|---|---|
| ChatGPT | `chatgpt.com/backend-api/conversations?offset=&limit=`（带 `update_time`） | `…/backend-api/conversation/<id>`，从 `current_node` 沿 `parent` 走回开头 | `message.create_time` | [pionxzh/chatgpt-exporter](https://github.com/pionxzh/chatgpt-exporter) `src/api.ts` |
| Claude | `claude.ai/api/organizations/<org>/chat_conversations`（带 `updated_at`） | `…/chat_conversations/<id>?tree=True&rendering_mode=messages`，从 `current_leaf_message_uuid` 沿 `parent_message_uuid` 走回开头 | `created_at` | [agoramachina/claude-exporter](https://github.com/agoramachina/claude-exporter) `chrome/content.js`、`chrome/utils.js` |
| Gemini | 先不做，见第 10 节 | | | |

规则（ADR 0010 第 2 条）：

- **请求只在网站自己的网页里发**，用网页已有的登录状态。ChatGPT 要先向 `chatgpt.com/api/auth/session` 取一个临时令牌，只在这个网页里用来发请求，**不存下来、不发给 eia、不发到任何别的地方**。插件不读 cookie、不读密码。
- **只读不写**：只用取数据的接口，不发消息、不改、不删任何东西。
- **限速**：一次一个请求，每个对话之间隔 2 秒；网站回「太频繁」（HTTP 429）就按它说的时间等，没说就等 60 秒；同一天连续 3 次被限就停到明天。
- 这些接口没有公开，随时可能变：认不出返回的格式就停下、图标标红，不写任何文件（第 7 节）。

## 3. 不做什么

- 不在浏览器外面用你的登录状态（不导出 cookie、令牌给 eia 或命令行），这是 `docs/ROADMAP.md`「明确不做」那一条真正要防的。
- 不发到外面：插件只把内容发到你自己电脑上的 eia（`127.0.0.1`），不经过任何服务器，也不调用 AI。
- 不读 App 存在本机的文件（格式没公开、可能加密）。
- 不做聊天时实时同步；每天一次够用，以后要再加。
- 不导入思考过程、附件内容、图片（附件留占位，和导入一致）。Claude 的 projects、artifacts 不同步。
- 不做 Firefox、Safari、手机浏览器。

## 4. 组成

```
浏览器（Chrome / Edge）                           你的电脑
┌──────────────────────────────┐  POST JSON   ┌──────────────────────────────┐
│ 插件：每天一次                    │ ──────────▶ │ eia sync serve（只听 127.0.0.1） │
│ 在已登录的网页里请求对话列表        │  带口令      │ 核对口令 → 转成对话 → 复用导入程序 │
│ → 挑出更新过的 → 逐个取内容         │ ◀────────── │ 写 chats/<平台>/…md              │
└──────────────────────────────┘  结果        └──────────────────────────────┘
```

### 4.1 插件

- 自己写一个小插件（Manifest V3），纯 JavaScript、不用构建；请求和「沿父节点走回开头」的代码改写自上表两个项目，保留原版权声明，写进 `THIRD_PARTY_NOTICES.md`。
- 权限只要 `chatgpt.com`、`claude.ai`、`http://127.0.0.1`，和定时用的 `alarms`、存进度用的 `storage`。
- **发给 eia 的**：网站返回的**原始对话 JSON**（不在插件里转换），加上平台名。这样转换代码在 eia 里，用 Python 写、用 pytest 测，和导入官方导出包共用同一套规则；网站改了格式，修 eia 就行，不用重装插件。
- **点插件图标**：上次同步的时间和结果、「现在同步」、暂停，或者只关某个网站。

### 4.2 每天怎么同步

- **什么时候**：每天第一次打开浏览器 10 分钟后开始；当天成功了就不再跑。eia 没开、中途关了浏览器，之后每小时再试，从断开的地方接着来。
- 插件需要一个这个网站的标签页来发请求：你开着就用你的（不切过去、不打扰你）；没开就在后台开一个，跑完关掉。没登录就跳过这个网站，图标上提示。
- **挑哪些对话**：取对话列表（编号 + 更新时间）发给 eia，**由 eia 和 vault 比**：vault 里没有的、网站上的更新时间比 vault 里新的才要取（ADR 0010 第 7 条）。
  - 第一次：vault 里没有或者变了的全部取；之前用官方导出包导入过、没变的不再取。
  - 之后：一般只有当天聊过的几个。
- 逐个取内容，发给 eia；中途停了，下次再问 eia 一遍，已经写进 vault 的自然不会再取。
- 第一次同步你约 1,000 个 ChatGPT 和 Claude 对话，按每个 2 秒，大约半小时到一小时；之后每天一般几个到几十个，一两分钟。

### 4.3 eia 这边：`eia sync serve`

```powershell
eia sync serve --vault <vault> [--port 8771]  # 前台运行，Ctrl+C 停止
eia sync autostart --vault <vault>            # 登录 Windows 时自动在后台运行，现在也马上启动；--remove 取消
eia sync token --vault <vault>                # 显示插件要填的口令（第一次运行时自动生成）
eia sync status --vault <vault>               # 最近同步了哪些、有没有失败
```

- 只监听 `127.0.0.1`，端口默认 `8771`，用 `--port` 改；插件设置里填同一个端口。
- **口令**：随机生成，存在 `.eia/eia.db`（不放 vault 的 Markdown 里，不进 git）。请求不带对的口令就拒绝。这样别的网页即使知道端口，也写不进你的 vault。
- 单次最大 20 MB；不认识的平台、认不出的 JSON 直接拒绝并返回原因，不写文件。
- **转换**：ChatGPT 的对话 JSON 和官方导出包里每个对话的格式基本相同，复用 `chat/chatgpt.py` 的解析（`current_node` 路径、角色、文字）；Claude 的复用 `chat/claude.py`（`text` 块、沿 `parent_message_uuid` 走到最新、附件只留占位）。两边有差别的地方实现前用真实返回核对，只记字段名和类型，不读内容（和 Gemini 规格第 2 节的做法一样）。
- 写文件完全照导入的规则：按 `platform + conversation_id` 找已有文件；只改标记之间的内容和 frontmatter 的少数字段，**你加的标签、自加字段、标记下面的笔记都保留**；标记损坏、YAML 坏掉的文件不碰；消息比文件里少时不改（防止哪次没取全冲掉内容）。
- 每个对话回一个结果：「新建」「更新」「未变」「跳过（原因）」。运行记录只记平台、对话编号、消息数、结果，不记内容。

## 5. 和官方导出包的关系（不重复）

对话编号和官方导出包里的一样（ChatGPT 的 `conversation_id`、Claude 的 `uuid`），内容和时间也来自同一份数据。所以同一个对话，先同步还是先导入官方包都是同一个文件，谁更新就以谁为准，和现在重复导入的规则一样。不需要 `time_approx`、`partial` 这类标记。

## 6. 隐私

- 内容只在你的浏览器和你的电脑之间传，不出电脑。
- 登录状态只在网站自己的网页里用，插件不存、不外传（第 2 节）。
- 源码在本仓库，可以自己看。

## 7. 出错时

| 情况 | 处理 |
|---|---|
| 没登录、令牌取不到 | 跳过这个网站，图标提示「请先登录」 |
| 被限速（429） | 按第 2 节等待；同一天 3 次就停到明天 |
| 接口返回的格式认不出（网站改版） | eia 回「跳过：格式认不出」，不写文件；同一个网站连续 3 个对话这样就停下，图标标红 |
| eia 没开 | 不取内容，每小时再试 |

## 8. 验收（登记到 docs/TEST-PLAN.md）

eia 这边全部用 pytest 测，用合成的、按真实字段结构写的 JSON；插件的列表比较、限速、进度用 Node 自带的测试工具测（第 9 节第 2 条）。

| 编号 | 验收标准 |
|---|---|
| F19-01 | 没有口令、口令错、不是 `127.0.0.1` 的请求一律拒绝，不写任何文件 |
| F19-02 | ChatGPT 对话 JSON 转成合规的 chat 文件：只取 `current_node` 路径，每条消息的时间来自 `create_time`；`validate` 通过 |
| F19-03 | Claude 对话 JSON 转成合规的 chat 文件：走到最新的分支，时间来自 `created_at`，附件只留占位 |
| F19-04 | 同一个对话先同步、再导入官方导出包（或反过来）：同一个文件，不重复；你加的标签、自加字段、笔记保留 |
| F19-05 | 同样的内容再发一次回「未变」、不改文件；消息比文件里少时不改 |
| F19-06 | 不认识的平台、认不出的 JSON、超大的请求返回原因，服务不停 |
| F19-07 | 运行记录只有平台、编号、消息数、结果，没有对话内容；请求里不出现登录令牌 |
| F19-08 | 插件挑对话：第一次全部；之后只挑更新时间变新的和没同步过的；eia 回成功才记下；中断后接着跑 |
| F19-09 | 插件限速：对话之间至少隔 2 秒；429 按 `Retry-After` 等；一天 3 次就停 |

## 9. 已决定（2026-11-27 作者）

1. **插件怎么来**：自己写一个小插件，纯 JavaScript、不用构建，只改写两个开源项目里请求接口和走对话树的代码（保留版权声明）；不 fork 整个项目。开源项目里没有能直接用的：都要手动点导出，没有定时、没有发到本机、没有增量记录（2026-11-27 查过 chatgpt-exporter、claude-exporter、obsidian-AI-exporter、gemini-export 等）。
2. **插件的测试**：放在插件目录，用 Node 自带的测试工具跑，不放进 `check.py`；eia 这边的测试照常在 `check.py` 里。
3. **安装方式**：先只支持「开发者模式 → 加载已解压的扩展程序」（README 写步骤），上架 Chrome 应用商店以后再说。
4. **默认开不开**：装了插件就默认都同步；可以在插件里关掉某个网站。
5. **每天一次**：第一次全部，之后只要更新过的；不做实时同步。
6. **走网站的接口**，不读页面文字：有准确时间、长对话一次取全、按更新时间判断哪些变了（ADR 0010）。

## 10. 已知局限

- **Gemini 这一版不做**：它的网页接口（`batchexecute`）返回的是没有字段名、层层嵌套的数组，靠位置猜含义，比另外两家难得多，这次也没找到能参考的开源代码。Gemini 先继续用你现在的 Gemini 导出插件 + `eia import gemini`；以后单独研究，写 delta spec。
- 浏览器要开过、登录着网站，eia 要在后台运行；当天没开浏览器就第二天补。
- 一天同步一次，今天聊的最晚明天才进 vault；想马上同步就点「现在同步」。
- 临时对话不在对话列表里，同步不到；在网站上删掉的对话，vault 里会留着。
- 接口不公开，网站改版就可能失效，要修 eia 的转换或插件的请求；失效期间不会写坏文件。
- 平台条款不鼓励自动取数据；限速和每天一次是为了把影响降到和你自己翻看差不多，但风险不是零（ADR 0010 第 3 条）。
