# Spec: chat-sync（浏览器插件自动同步对话）

Status: 草案 2026-11-27（第 9 节四项作者已按推荐同意；第 3.3 节「补漏」是作者追加的要求，等确认）　版本：V2
依赖：`docs/specs/chat-import.md`（重复导入、标记块、保留用户内容）、`docs/specs/chat-import.delta-gemini.md` 第 4 节（消息变少时不更新）
在总目标里的位置：第 1 层「采集」（`docs/ROADMAP.md` 开头）

## 1. 要解决的问题

现在要更新对话，得去网站点导出、等邮件、下载、再运行 `eia import`。所以 vault 里的对话总是落后几周，画像也跟着落后。

目标：

- 在电脑浏览器里用 ChatGPT、Claude、Gemini 网页版聊天时，**每次 AI 回复完，这个对话自动写进 vault**，你什么都不用做。
- 在**电脑 App、手机 App** 上聊的，也要自动同步（作者 2026-11-27 追加：现在很多人用 App 而不是网页）。见第 3.3 节。

## 2. 不做什么

- **不碰账号**：不读密码、cookie、登录凭据，不调用网站的内部接口（`docs/ROADMAP.md`「明确不做」），只读你正在看的页面上显示的文字。
- **不发到外面**：插件只把内容发到你自己电脑上的 eia（`127.0.0.1`），不经过任何服务器，也不调用 AI。
- **不读 App 的本地文件**：ChatGPT、Claude 电脑 App 存在本机的缓存格式没有公开、随时会变，也可能被加密，不去读。App 上的对话靠第 3.3 节从网页补。
- **不补很久以前的历史**：补漏只看最近更新的对话；以前的对话还是靠导一次官方导出包（第 6 节保证两者不重复）。
- 不导入思考过程、附件内容、图片（附件留占位，和导入一致）。
- 不做 Firefox、Safari、手机浏览器。

## 3. 组成

```
浏览器（Chrome / Edge）                       你的电脑
┌──────────────────────────┐   POST JSON   ┌─────────────────────────────┐
│ 插件：每个网站一个读取器   │ ───────────▶ │ eia sync serve（只听 127.0.0.1）│
│ 等 AI 回复完 → 读页面文字  │  带口令       │ 核对口令 → 合并 → 复用导入程序  │
│ eia 没开时先存着，稍后重发  │ ◀─────────── │ 写 chats/<平台>/…md             │
└──────────────────────────┘   结果         └─────────────────────────────┘
```

### 3.1 插件

- 基于开源项目 [obsidian-AI-exporter](https://github.com/sho7650/obsidian-AI-exporter)（MIT）的各网站读取代码改写，保留原版权声明，写进 `THIRD_PARTY_NOTICES.md`。做法见第 9 节第 1 条。
- 只在三个网站上运行：`chatgpt.com`、`claude.ai`、`gemini.google.com`；权限只要这三个网站和 `http://127.0.0.1`。
- **什么时候发**：AI 回复完（「停止生成」按钮消失）后再等 3 秒，页面没有新变化就发；切走标签页、关闭页面前再发一次。同一个对话内容没变就不发。
- **发什么**（JSON）：

  | 字段 | 内容 |
  |---|---|
  | `platform` | `chatgpt` / `claude` / `gemini` |
  | `conversation_id` | 从网址取（第 6 节） |
  | `url`、`title` | 当前网址、页面上的对话标题 |
  | `messages[]` | 页面上**目前加载出来的**消息，按顺序，每条 `role`（`user` / `assistant`）和 `text`（Markdown）；页面上有时间的带 `time` |
  | `model` | 页面上显示的模型名，读不到就不填 |

- **eia 没开时**：每个对话只存最新一份，存在插件自己的存储里；之后每分钟试一次，发出去就删。插件图标上显示还有几个没发。
- **开关**：点插件图标可以暂停同步，或者只关某个网站。网址里没有对话编号的（ChatGPT 临时对话、新建还没发送的）不同步。

### 3.2 eia 这边：`eia sync serve`

```powershell
eia sync serve --vault <vault>       # 前台运行，Ctrl+C 停止
eia sync token --vault <vault>       # 显示插件要填的口令（第一次运行时自动生成）
eia schedule add sync --vault <vault>  # 登录 Windows 时自动在后台启动（复用 scheduler 模块）
```

- 只监听 `127.0.0.1`，端口默认 `8771`，可在 `config.yaml` 的 `sync.port` 改；插件选项里填同一个端口。
- **口令**：随机生成，存在 `.eia/eia.db`（不放 vault 的 Markdown 里，不进 git）。请求不带对的口令就拒绝。这样别的网页即使知道端口，也写不进你的 vault。
- 只接受上面的 JSON，单次最大 20 MB；不认识的平台、没有消息的对话直接拒绝并返回原因。
- 每收到一次写一行运行记录（只记平台、对话编号、消息数、结果，不记内容），`eia sync status` 能看最近同步了哪些、有没有失败。

### 3.3 补漏：同步在 App 和手机上聊的

电脑 App、手机 App 和网页用的是同一个账号，在 App 上聊的对话，网页的侧边栏里也会出现。所以插件定时去网页上看一眼，把最近更新过的对话读回来：

- **多久一次**：默认每 30 分钟；浏览器开着、你登录着这个网站时才做。`config.yaml` 不管这个，在插件选项里改。
- **怎么做**：在后台开一个不打扰你的标签页，打开网站，读侧边栏的对话列表（按最近更新排）。从最上面往下，逐个打开、读页面、按第 4 节合并，**遇到一个内容和 vault 里一样的就停**。
- **限量**：每次最多打开 10 个对话，每个之间隔几秒；你正在用这个网站的标签页里聊天时不做，避免打扰、也避免看起来像机器在刷网站。
- 第一次运行只记下侧边栏目前最上面的是哪个，不往回补（往回补用官方导出包）。
- 这仍然只是在你自己登录的浏览器里**打开网页、读页面上的文字**，不调内部接口、不碰账号；网站改版时和第 3.1 节一样会失效。

限制：

- 浏览器要开着（可以最小化）。电脑关机期间在手机上聊的，下次开浏览器时补上。
- 侧边栏不显示对话的更新时间，只能按顺序判断；你在网页上把旧对话「置顶」之类的操作可能让它多读几个，不会读错。
- 手机 App 里的「临时对话」不会出现在侧边栏，同步不到。

## 4. 合并：页面上不一定是完整的对话

长对话里，网站常常只加载最近的一部分，往上滚才加载更早的。所以插件发来的可能只是对话的后半段。处理规则：

| 情况 | 处理 |
|---|---|
| vault 里还没有这个对话 | 新建文件。消息只有页面上加载出来的这些，frontmatter 记 `partial: true`（第 6 节用到） |
| 页面的第一条消息能在文件里找到（按说话方 + 正文完全一致） | 文件里它之前的消息保留，从它开始以页面为准（新增的追加；你在网页上重新生成的回复会替换旧的） |
| 页面的第一条消息在文件里找不到，但页面的消息数 ≥ 文件里的 | 整个以页面为准 |
| 都不是 | 不修改，记「跳过：页面上的对话对不上文件，可能没加载完」 |

其余和导入完全一样：只改标记之间的内容和 frontmatter 的少数字段，**你加的标签、自加字段、标记下面的笔记都保留**；标记损坏、YAML 坏掉的文件不碰。

## 5. 时间

ChatGPT 和 Claude 页面上不显示每条消息的时间（Gemini 也不一定有）。规则：

- 页面上有时间就用页面的。
- 没有时：文件里已有的消息**保留文件里的时间**；新出现的消息用 eia **第一次收到它的时间**，并在 frontmatter 记 `time_approx: true`。
- 因为插件在 AI 回复完几秒内就发，这个时间一般只差几秒到几分钟；但如果 eia 没开、插件稍后重发，时间会晚于实际。

## 6. 和官方导出包的关系（不重复）

对话编号和官方导出一致，所以同一个对话，不管先同步还是先导入，都是同一个文件：

| 平台 | 网址 | `conversation_id` | 和官方导出 |
|---|---|---|---|
| ChatGPT | `chatgpt.com/c/<id>` | `<id>` | 与官方导出的 `conversation_id` 相同（实现前用你的 vault 核对） |
| Claude | `claude.ai/chat/<uuid>` | `<uuid>` | 与官方导出的 `uuid` 相同（同上） |
| Gemini | `gemini.google.com/…/app/<id>` | `c_<id>` | 与 Gemini 插件导出的格式相同（vault 里已确认） |

**之后再导入官方导出包**时：文件里记着 `time_approx: true` 或 `partial: true` 的，只要官方包的消息数 ≥ 文件里的，就用官方的内容和时间替换，并去掉这两个标记——官方导出是更准的来源。其他情况照原来的导入规则。

## 7. 隐私

- 内容只在你的浏览器和你的电脑之间传，不出电脑。
- 插件不读 cookie、不读其他网站，源码在本仓库，可以自己看。
- 网站改版后读取器可能读错或读不到：读不到时插件图标标红、不发送；**读到的消息比文件里少时按第 4 节不修改**，不会冲掉已有内容。

## 8. 验收（登记到 docs/TEST-PLAN.md）

eia 这边全部用 pytest 测（合成数据）；插件的读取器用保存下来的、去掉真实内容的页面片段测（第 9 节第 2 条）。

| 编号 | 验收标准 |
|---|---|
| F19-01 | 没有口令、口令错、不是 `127.0.0.1` 的请求一律拒绝，不写任何文件 |
| F19-02 | 新对话建成合规的 chat 文件，`validate` 通过；重复发同样的内容不改文件 |
| F19-03 | 页面只有后半段时按第 4 节合并：之前的消息保留、新的追加、重新生成的回复替换；对不上时跳过、不改文件 |
| F19-04 | 你加的标签、自加字段、标记下面的笔记在同步后保留 |
| F19-05 | 没有时间的消息：已有的保留文件里的时间，新的用收到的时间，记 `time_approx: true` |
| F19-06 | 同步过的对话再导入官方导出包：同一个文件，不产生重复；官方消息更多时替换内容和时间、去掉 `time_approx` / `partial` |
| F19-07 | 不认识的平台、坏的 JSON、超大的请求返回原因，服务不停 |
| F19-08 | 运行记录只有平台、编号、消息数、结果，没有对话内容 |
| F19-09 | 三个网站的读取器从保存的页面片段读出正确的说话方、正文和对话编号 |
| F19-10 | 补漏：从保存的侧边栏片段按顺序选出要打开的对话，遇到和 vault 一样的就停，每次不超过 10 个；第一次运行不往回补 |

## 9. 已决定（2026-11-27 作者同意按推荐）

1. **插件怎么来**（推荐 a）
   - a. **自己写一个小插件，用纯 JavaScript、不用构建**：只把 obsidian-AI-exporter 的三个网站读取代码改写过来（保留版权声明）。好处：代码少、能直接「加载已解压的扩展程序」，不用装 Node.js；只有我们要的功能。
   - b. **直接 fork 整个 obsidian-AI-exporter**：功能多（Perplexity、NotebookLM、手动导出按钮），但要装 Node.js 构建，大部分代码用不上，跟上游合并也麻烦。
2. **插件的测试**（推荐 a）
   - a. 读取器的测试放在插件目录，用 Node 自带的测试工具跑，**不放进 `check.py`**；eia 这边的测试照常在 `check.py` 里。
   - b. 都放进 `check.py`：每个开发者都要装 Node.js。
3. **安装方式**：先只支持「开发者模式 → 加载已解压的扩展程序」（README 写步骤），上架 Chrome 应用商店以后再说。（推荐）
4. **默认开不开**：装了插件就默认三个网站都同步；你可以在插件里关掉某个网站。（推荐）

## 10. 已知局限

- 电脑 App、手机 App 上的聊天要等浏览器开着、补漏跑到时才同步，最多晚 30 分钟；临时对话同步不到。
- 网站改版就可能失效，需要修读取器；失效期间不会写坏文件，但那段时间的对话要靠官方导出补。
- 没有时间的平台，时间是近似的（第 5 节）。
- 只同步你打开过的对话；在网页上删掉的消息，vault 里会留着（和 Gemini 导入一样）。
