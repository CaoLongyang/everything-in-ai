# Spec: chat-sync（浏览器插件每天自动同步对话）

Status: 草案 2026-11-27（第 9 节四项作者已按推荐同意；2026-11-27 作者改为「每天同步一次，第一次全部、之后只要更新过的」，等确认）　版本：V2
依赖：`docs/specs/chat-import.md`（重复导入、标记块、保留用户内容）、`docs/specs/chat-import.delta-gemini.md` 第 4 节（消息变少时不更新）
在总目标里的位置：第 1 层「采集」（`docs/ROADMAP.md` 开头）

## 1. 要解决的问题

现在要更新对话，得去网站点导出、等邮件、下载、再运行 `eia import`。所以 vault 里的对话总是落后几周，画像也跟着落后。

目标：**每天自动把 ChatGPT、Claude、Gemini 上的对话同步进 vault，你什么都不用做。**

- 不管你是在网页、电脑 App 还是手机 App 上聊的，都要同步得到（作者 2026-11-27：现在很多人用 App 而不是网页）。App 和网页是同一个账号，App 上的对话网页侧边栏里也有，所以插件从网页读。
- 第一次同步全部对话；之后每天只同步更新过的。

## 2. 不做什么

- **不碰账号**：不读密码、cookie、登录凭据，不调用网站的内部接口（`docs/ROADMAP.md`「明确不做」），只在你自己登录的浏览器里打开网页、读页面上显示的文字。
- **不发到外面**：插件只把内容发到你自己电脑上的 eia（`127.0.0.1`），不经过任何服务器，也不调用 AI。
- **不读 App 的本地文件**：ChatGPT、Claude 电脑 App 存在本机的缓存格式没有公开、随时会变，也可能被加密。
- 不做聊天时实时同步（每回复一次就同步）：每天一次够用，以后要再加。
- 不导入思考过程、附件内容、图片（附件留占位，和导入一致）。
- 不做 Firefox、Safari、手机浏览器。

## 3. 组成

```
浏览器（Chrome / Edge）                        你的电脑
┌───────────────────────────┐   POST JSON   ┌──────────────────────────────┐
│ 插件：每天一次                │ ───────────▶ │ eia sync serve（只听 127.0.0.1） │
│ 后台标签页打开网站 → 读侧边栏  │  带口令       │ 核对口令 → 合并 → 复用导入程序   │
│ → 逐个打开对话 → 读页面文字    │ ◀─────────── │ 写 chats/<平台>/…md；回「未变」  │
└───────────────────────────┘   结果         └──────────────────────────────┘
```

### 3.1 插件

- 自己写一个小插件，纯 JavaScript、不用构建；三个网站的读取代码改写自开源项目 [obsidian-AI-exporter](https://github.com/sho7650/obsidian-AI-exporter)（MIT），保留原版权声明，写进 `THIRD_PARTY_NOTICES.md`（第 9 节第 1 条）。
- 只在三个网站上运行：`chatgpt.com`、`claude.ai`、`gemini.google.com`；权限只要这三个网站和 `http://127.0.0.1`。
- **发什么**（每个对话一次，JSON）：

  | 字段 | 内容 |
  |---|---|
  | `platform` | `chatgpt` / `claude` / `gemini` |
  | `conversation_id` | 从网址取（第 6 节） |
  | `url`、`title` | 网址、页面上的对话标题 |
  | `messages[]` | 按顺序，每条 `role`（`user` / `assistant`）和 `text`（Markdown）；页面上有时间的带 `time` |
  | `complete` | 插件是否已经往上滚到了对话开头、加载出全部消息 |
  | `model` | 页面上显示的模型名，读不到就不填 |

- **开关**：点插件图标能看上次同步的时间和结果、「现在同步」、暂停，或者只关某个网站。

### 3.2 每天怎么同步

- **什么时候**：每天第一次打开浏览器 10 分钟后开始；当天跑成功了就不再跑。eia 没开、跑到一半关了浏览器，之后每小时再试，从断开的地方接着跑。
- **怎么跑**：对每个开着同步的网站，在后台开一个标签页（不切过去、不打扰你），打开网站：
  1. 读侧边栏的对话列表（按最近更新排，置顶的那一组跳过）。
  2. 从最上面往下，逐个打开对话，往上滚到开头把消息加载完，读页面，发给 eia。
  3. **停的条件**：
     - **第一次**：侧边栏往下滚到底，全部对话都打开一遍。
     - **之后**：eia 回「未变」（和 vault 里一模一样）就停，后面的都是更早更新的。
- **速度**：一次只开一个对话，每个之间隔 3–5 秒，避免看起来像机器在刷网站。第一次全部对话可能要几个小时，可以中途关浏览器，下次接着跑；之后每天一般只有几个到几十个，几分钟就完。
- 每天最多打开 300 个对话（第一次不限），防止哪里出错一直跑下去。
- 你正在用这个网站的标签页里聊天时（页面正在生成回复），等它停下再继续。
- 某个对话读失败（页面没加载出来、读取器认不出），跳过它、记下来、明天再试；连续失败 5 个就停掉这个网站，插件图标标红，可能是网站改版了。

### 3.3 eia 这边：`eia sync serve`

```powershell
eia sync serve --vault <vault>         # 前台运行，Ctrl+C 停止
eia sync token --vault <vault>         # 显示插件要填的口令（第一次运行时自动生成）
eia sync status --vault <vault>        # 最近几次同步了哪些、有没有失败
eia schedule add sync --vault <vault>  # 登录 Windows 时自动在后台启动（复用 scheduler 模块）
```

- 只监听 `127.0.0.1`，端口默认 `8771`，可在 `config.yaml` 的 `sync.port` 改；插件选项里填同一个端口。
- **口令**：随机生成，存在 `.eia/eia.db`（不放 vault 的 Markdown 里，不进 git）。请求不带对的口令就拒绝。这样别的网页即使知道端口，也写不进你的 vault。
- 只接受上面的 JSON，单次最大 20 MB；不认识的平台、没有消息的对话直接拒绝并返回原因。
- 每个对话回一个结果：「新建」「更新」「未变」「跳过（原因）」。插件靠「未变」决定什么时候停。
- 运行记录只记平台、对话编号、消息数、结果，不记内容。

## 4. 合并：页面上不一定是完整的对话

插件会尽量往上滚加载完整对话，但很长的对话可能加载不全（`complete: false`）。处理规则：

| 情况 | 处理 |
|---|---|
| vault 里还没有这个对话 | 新建文件；没加载全的，frontmatter 记 `partial: true`（第 6 节用到） |
| 页面的第一条消息能在文件里找到（按说话方 + 正文完全一致） | 文件里它之前的消息保留，从它开始以页面为准（新增的追加；你在网页上重新生成的回复会替换旧的） |
| 页面的第一条消息在文件里找不到，但 `complete: true` 且页面的消息数 ≥ 文件里的 | 整个以页面为准 |
| 都不是 | 不修改，回「跳过：页面上的对话对不上文件，可能没加载完」 |

其余和导入完全一样：只改标记之间的内容和 frontmatter 的少数字段，**你加的标签、自加字段、标记下面的笔记都保留**；标记损坏、YAML 坏掉的文件不碰。

## 5. 时间

ChatGPT 和 Claude 页面上不显示每条消息的时间（Gemini 也不一定有）。规则：

- 页面上有时间就用页面的。
- 没有时：文件里已有的消息**保留文件里的时间**；新出现的消息用 eia **收到它的时间**，并在 frontmatter 记 `time_approx: true`。
- 每天同步一次，所以新消息的时间最多差一天左右。
- **第一次同步时 vault 里还没有的对话**，时间全部是同步那天，可能差得很远。你的 vault 已经用官方导出包导入过，大部分对话已经在了，影响不大；以后再导一次官方导出包就能改正（第 6 节）。

## 6. 和官方导出包的关系（不重复）

对话编号和官方导出一致，所以同一个对话，不管先同步还是先导入，都是同一个文件：

| 平台 | 网址 | `conversation_id` | 和官方导出 |
|---|---|---|---|
| ChatGPT | `chatgpt.com/c/<id>` | `<id>` | 与官方导出的 `conversation_id` 相同（实现前用你的 vault 核对） |
| Claude | `claude.ai/chat/<uuid>` | `<uuid>` | 与官方导出的 `uuid` 相同（同上） |
| Gemini | `gemini.google.com/…/app/<id>` | `c_<id>` | 与 Gemini 插件导出的格式相同（vault 里已确认） |

**之后再导入官方导出包**时：文件里记着 `time_approx: true` 或 `partial: true` 的，只要官方包的消息数 ≥ 文件里的，就用官方的内容和时间替换，并去掉这两个标记——官方导出是更准的来源。其他情况照原来的导入规则。

## 7. 隐私

- 内容只在你的浏览器和你的电脑之间传，不出电脑。
- 插件不读 cookie、不读其他网站，源码在本仓库，可以自己看。
- 网站改版后读取器可能读错或读不到：读不到时跳过、图标标红；**读到的消息比文件里少时按第 4 节不修改**，不会冲掉已有内容。

## 8. 验收（登记到 docs/TEST-PLAN.md）

eia 这边全部用 pytest 测（合成数据）；插件的读取器和同步顺序用保存下来的、去掉真实内容的页面片段测（第 9 节第 2 条）。

| 编号 | 验收标准 |
|---|---|
| F19-01 | 没有口令、口令错、不是 `127.0.0.1` 的请求一律拒绝，不写任何文件 |
| F19-02 | 新对话建成合规的 chat 文件，`validate` 通过；重复发同样的内容不改文件、回「未变」 |
| F19-03 | 页面只有后半段时按第 4 节合并：之前的消息保留、新的追加、重新生成的回复替换；对不上时跳过、不改文件 |
| F19-04 | 你加的标签、自加字段、标记下面的笔记在同步后保留 |
| F19-05 | 没有时间的消息：已有的保留文件里的时间，新的用收到的时间，记 `time_approx: true` |
| F19-06 | 同步过的对话再导入官方导出包：同一个文件，不产生重复；官方消息更多时替换内容和时间、去掉 `time_approx` / `partial` |
| F19-07 | 不认识的平台、坏的 JSON、超大的请求返回原因，服务不停 |
| F19-08 | 运行记录只有平台、编号、消息数、结果，没有对话内容 |
| F19-09 | 三个网站的读取器从保存的页面片段读出正确的说话方、正文和对话编号 |
| F19-10 | 同步顺序：第一次按侧边栏全部打开；之后从上往下，遇到「未变」就停、跳过置顶；每天不超过 300 个；中断后从断开处接着跑 |

## 9. 已决定（2026-11-27 作者同意按推荐）

1. **插件怎么来**：自己写一个小插件，纯 JavaScript、不用构建，只把 obsidian-AI-exporter 的三个网站读取代码改写过来（保留版权声明）；不 fork 整个项目。
2. **插件的测试**：放在插件目录，用 Node 自带的测试工具跑，不放进 `check.py`；eia 这边的测试照常在 `check.py` 里。
3. **安装方式**：先只支持「开发者模式 → 加载已解压的扩展程序」（README 写步骤），上架 Chrome 应用商店以后再说。
4. **默认开不开**：装了插件就默认三个网站都同步；可以在插件里关掉某个网站。

## 10. 已知局限

- 浏览器要开过、登录着这三个网站，eia 要在后台运行；当天没开浏览器就第二天补。
- 一天同步一次，今天聊的最晚明天才进 vault；想马上同步就点「现在同步」。
- 临时对话不会出现在侧边栏，同步不到；在网页上删掉的对话和消息，vault 里会留着（和 Gemini 导入一样）。
- 网站改版就可能失效，需要修读取器；失效期间不会写坏文件。
- 没有时间的平台，时间是近似的（第 5 节）。
