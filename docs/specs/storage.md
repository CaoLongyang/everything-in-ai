# Spec: storage（SQLite 数据库）

Status: 已批准 2026-11-21（第 9 节：做全文搜索；兴趣历史不导出）　版本：V1
改动的原则：`docs/CAPABILITY-MAP.md` 原则 1「纯 Markdown 是唯一数据源」改为「**Markdown 是内容的唯一来源**；机器用的数据放 SQLite」。
作者 2026-11-21 选定：内容用 Markdown，其余用 SQLite；现在做，放在 V1 剩下的功能前面。

## 1. 为什么

2026-11-21 作者的真实 vault 里，除了 988 个 Markdown，已经有 7 个格式各异的数据文件：

| 文件 | 大小 | 问题 |
|---|---|---|
| `.eia/headlines/items.jsonl` | 197 KB | 每次整个读、整个重写 |
| `.eia/headlines/vectors.json` | 6 MB | 向量用文本存，读一次要解析几百万个数字 |
| `.eia/interests/vectors.json` | 18 MB | 同上；是网站和归组慢、占内存的原因之一 |
| `.eia/interests/shown.json`、`.eia/runs/*.jsonl` | 小 | 各自一套读写代码 |
| `interests/feedback.jsonl` | 小 | 用户数据，查询要全读 |

以后的看板、画像、兴趣历史、网页剪藏都需要「按条件查」（例如「最近 30 天标过不相关的财经报道」），散文件做不了。

## 2. 分工

| 数据 | 放哪 | 删掉会怎样 |
|---|---|---|
| 你看、你改的内容：对话、大事、今日兴趣、笔记、兴趣草稿 | Markdown（不变） | —— |
| 你的设置和确认过的兴趣 | `config.yaml`（不变） | —— |
| 你的评价 | **SQLite + 每次写入同时导出** `interests/feedback.jsonl` | 数据库删了能从导出文件恢复 |
| 所有条目的索引：路径、类型、标题、时间、标签、平台、来源 | SQLite，从 Markdown 自动生成 | 重建即可 |
| 抓到的报道、向量、运行记录、「已经给你看过」、兴趣的历史版本 | SQLite | 报道重新抓、向量重新算；运行记录和历史会丢（不是你写的内容） |

**数据库永远可以删掉重建**：`eia db rebuild` 从 Markdown 和导出文件重新生成，只损失缓存。

## 3. 数据库

- 一个文件：`.eia/eia.db`（`.eia/` 已在 `.gitignore`，不进 Git）。Python 自带 `sqlite3`，不用装服务器、不联网。
- 开启 WAL 模式和 5 秒等待：定时任务和网站同时读写时不会出错。
- 表结构有版本号（`schema_version`），以后加字段用迁移脚本，不让用户手动处理。

| 表 | 内容 |
|---|---|
| `entries` | 每个 Markdown 条目一行：id、相对路径、type、title、created、updated、status、platform、source、修改时间、大小 |
| `entry_tags` | 条目的标签（一个标签一行，方便按标签查） |
| `items` | 新闻雷达抓到的报道（按规范化链接去重） |
| `vectors` | 向量：模型、命名空间（报道 / 对话 / 兴趣 / 评价）、键、维度、**二进制 float32**。模型变了按模型名作废 |
| `runs` | 定时任务的运行记录 |
| `shown` | 今日兴趣里给你看过的报道 |
| `feedback` | 评价（同时导出到 `interests/feedback.jsonl`） |
| `interest_history` | 每次 `accept` / 保存兴趣清单时存一份快照（给 V2 的「兴趣随时间的变化」） |

## 4. 索引怎么保持最新

- 每个命令开始时做一次**增量更新**：只重新读修改时间变了的 Markdown，删掉的文件从索引移除。974 个对话的增量检查预计 1 秒以内。
- eia 自己写 Markdown（导入、雷达、今日兴趣）时顺手更新索引。
- 你在 Obsidian 里改了文件，下次任何 eia 命令都会发现。

## 5. 迁移

第一次运行新版本时自动迁移，然后告诉你迁移了什么：
- 把上表里 7 个文件的内容导入数据库；
- `.eia/` 里的旧文件移到 `.eia/old/`（不删，确认没问题后你可以自己删）；
- `interests/feedback.jsonl` 留在原处，继续作为评价的导出文件。

## 6. 命令

```
eia db status    # 数据库大小、每张表多少行、索引是否最新
eia db rebuild   # 删掉重建：重新索引 Markdown、从导出文件恢复评价
```

## 7. 对现有代码的影响

只换「存在哪」，命令和行为不变：`headlines/store.py`、`interests/vectors.py`、`interests/feedback.py`、`interests/digest.py`（shown）、`schedule/runs.py`（运行记录）改成读写数据库。
网站和 `eia chats` / 文件浏览改用索引，列表不再每次扫描 988 个文件。

## 9. 作者的决定（2026-11-21）

1. **做全文搜索**：SQLite 的 FTS5，`trigram` 分词（中文可用）。3 个字及以上走全文索引；1–2 个字（如「汽车」）索引用不上，改为逐条比对，几千个条目也只要几十毫秒。
   如果用户电脑上的 SQLite 不支持 FTS5 / trigram（低于 3.34），搜索功能说明原因后不可用，其他功能照常。
2. **兴趣历史不导出**成文本，只在数据库里。
