# Roadmap（迭代计划）

原则：每个版本都是"能用的整体"。新想法一律先进 Backlog，版本进行中不扩范围；重新排期只在版本之间做。已批准的规格要改，写 delta spec（`docs/specs/<name>.delta-*.md`），不直接改旧 spec。

## V0 — 雏形：我的 AI 对话变成一个能浏览的知识库

使用者：作者 本人，Windows。不调用任何 AI，不联网抓取，不做定时任务。

| 功能 | 范围 |
|---|---|
| 创建 vault | `eia init`：目录结构 + 配置模板 + `.gitignore` |
| 格式检查 | `eia validate`：指出不合规的文件和字段 |
| 新建条目 | `eia new`：生成带合法 frontmatter 的空文件 |
| 导入 ChatGPT 对话 | 官方导出 zip → Markdown，一个对话一个文件；流式解析大文件；格式未知时明确报错 |
| 重复导入 | 按确定性 id 更新同一文件，不产生重复；**保留用户手动加的 tags 和未知字段** |
| 标签 | 用户在 Obsidian 里手动打，写进 frontmatter 的 `tags` |
| 浏览与搜索 | 直接用 Obsidian 打开 vault（不做网站） |
| 保持最新 | 用户定期手动官方导出并重新导入；重复导入只更新不重复，等效增量同步 |

完成标准：在 作者 的 Windows 机器上，按 README 完成"初始化 → 导入 ChatGPT 对话 → 在 Obsidian 里浏览、搜索、打标签 → 再次导入后标签仍在"。

状态：✅ 2026-11-20 完成。Claude 导入因官方导出迟迟未到，挪到 V1。

## V1 — 信息输入：大事不漏，兴趣有过滤

状态：✅ 2026-11-25 完成。Gemini 导入、剪藏验收、安装文档在最后一天收尾；`min_score` 校准、GitHub Actions 调度模板等挪到 V2 / Backlog（见下表和 Backlog）。

| 功能 | 范围 |
|---|---|
| `llm-adapter` | 单模型配置、`complete` / `complete_json` / `embed`、`eia llm test`（见 docs/specs/llm-adapter.md） |
| `headline-radar` | 抓取 → 聚类 → 独立来源计数 → 每日 `inbox/headlines/`；向量优先走 `llm-adapter.embed`，避免强制安装 torch |
| `interest-digest` | 从对话生成兴趣草稿、按兴趣过滤资讯、反馈后 AI 提炼兴趣（2026-11-21 取代原 `feed-digest` / `config-sync`：不接 Horizon，借鉴其架构，见 docs/specs/interest-digest.md） |
| `web-clip` | 剪藏插件模板对齐 schema |
| 调度 | `eia run <job>` + 本机定时（Windows 任务计划 / cron / launchd）；GitHub Actions 模板，runner 唯一负责 commit/push，同一 vault 只启用一种调度 |
| `chat-import` | 增加 Claude（官方导出，原 V0 项）和 Gemini（浏览器插件导出的 JSON，样例已有；Takeout 需换到第二个 Google 账号再试）；`--include-thinking` 选项，把模型思考过程以折叠块导入。**进度：Claude ✅ 2026-11-20；Gemini ✅ 2026-11-25（新版插件导出，带时间）** |
| `chat-reader` | 按说话方读取对话：可以只取「我」说的话，供 `llm-adapter` 之后的分析、画像、兴趣模块使用，避免把 AI 的观点当成用户的想法 |
| 可分发 | macOS / Linux / Windows 三系统 CI；面向其他用户的安装文档。**进度：CI ✅ 2026-11-20；安装和使用文档 ✅ 2026-11-25（README）** |

## V2 — 分析与闭环

| 功能 | 范围 |
|---|---|
| `knowledge-index` | 部署 Khoj 索引 vault；`config-sync` 扩展到 Khoj；定时研究简报 |
| `chat-sync` | 浏览器插件在聊天时实时把对话写成 vault 条目（ChatGPT / Claude / Gemini 网页版）；先评估现有开源插件能否复用；非官方方式，网站改版可能失效，独立模块、坏了不影响其他部分；不做模拟登录调用内部接口 |
| AI 自动打标签 / 摘要 | 需用户明确开启（会把对话内容发给所配置的 LLM） |
| 闭环 | 👍/👎 反馈；知识库内容反向调节兴趣过滤 |
| `takeout-import` | 通用 Google Takeout 导入（Gemini 之外：YouTube 观看/搜索/订阅、Chrome、搜索记录），按类别勾选；schema 新增 `activity` 类型（需单独 spec） |
| `activity-import` | TikTok 官方导出（JSON，选 All data）；B 站经浏览器插件导出的 JSON |
| `interest-bootstrap` | 从搜索、订阅、收藏、AI 对话等生成兴趣草稿（按信号强弱加权，观看记录权重最低），用户确认后才生效；需用户主动开启并能看到推断依据 |
| `chat-reader` 区分粘贴内容 | 「我」的消息里粘贴的文章、报错、AI 之前的回答，分析时不当成用户本人的想法（2026-11-21 从 V1 挪来；V1 的 chat-reader 不区分）。做法：规则能确定的在读取时直接标（与同一对话中 AI 之前的回答大段相同 = 贴回的 AI 回答；堆栈、成段代码），拿不准的标「疑似粘贴」，由 AI 在分析阶段结合上下文判断；粘贴内容不删，当作「关注了什么」而不是「认为什么」（2026-11-24 补充）。**应排在 `profile` 之前** |
| `headline-radar` AI 中文标题 | 给每条大事用 AI 写一句中文标题，默认关闭（2026-11-21 从 V1 挪来）；会把公开新闻标题发给所配置的 LLM |
| 兴趣分层与选择界面 | 兴趣分两层：大方向（如「科技」「信仰」「理财」）和具体话题；看板式页面，用户用**气泡选择**勾大致感兴趣的方向，再展开细化。V1 的兴趣草稿是第一版，只按对话频率归纳，混有课程作业和生活琐事（2026-11-21 作者提出）。兴趣过滤的 `min_score` 校准在这里做：用 `profile` / 分层选出的兴趣重测（2026-11-24 从 V1-8 挪来，初测数据见 ADR 0006 第 9 条） |
| 兴趣看板（dashboard） | 更好看的总览页：兴趣分布、每天挑出的资讯、评价统计、兴趣随时间的变化（2026-11-21 作者提出） |
| `profile` | 个人画像：AI 读取 vault 原文，生成"关于你"的结论，放在独立的 `profile/` 目录，与原始材料分开。从 3–4 个大类起步（参考结构：身份、价值观、认知、行为、关系、兴趣等），每条结论带来源条目 id（证据索引）；不确定的单列"未解问题"；画像按版本保留，可随时整份重新生成；AI 推断与用户本人的话分开标记；需用户明确开启（会把对话发给所配置的 LLM）。依赖 V0 对话导入与 V1 `llm-adapter` |
| 导入便利 | `eia import <folder>` 自动识别平台；监视 `exports\` 与 OneDrive 中的 Takeout 定时导出，新包自动导入 |

## 明确不做

| 项目 | 原因 |
|---|---|
| 微信聊天记录 | 无官方可读导出；第三方工具需破解本地数据库，腾讯 2026-01 已投诉下架 30+ 个此类开源项目；且包含他人隐私。重要内容由用户手动整理成笔记 |
| 抖音（凭登录凭据读取） | 无官方批量导出；现有工具需导入登录凭据，有封号与凭证泄露风险。待出现官方或更安全途径再评估 |
| 模拟登录调用平台内部接口 | 封号与凭证泄露风险，任何平台都不做 |

- 私密网站远程访问（带登录保护）
- 选择性公开发布 / 接入个人书卷网站
- 移动端推送（Telegram / 邮件）
- 自有 UI / 每日简报网页
- 调度：GitHub Actions 定时模板（vault 要推到 GitHub、云上用不了本机 Ollama，2026-11-21 从 V1 挪来）；运行失败时的系统通知；macOS / Linux 的 `eia schedule`
- `web-clip`（2026-11-24 作者提出）：「摘一句」模板，用选中句子的开头当文件名，同一篇文章摘多句时好区分；手机 App（微信、小红书等）经系统「分享」存进 Obsidian 的文字和链接，由 eia 补齐成合规的 `clip` 条目（web-clip 规格第 3 节方案 B 的做法）
- `chat-import`：Claude 导出中的 `projects`、`memories`、`artifact_data`（2026-11-20 定为以后再做）
- 新闻源（2026-11-21，见 `docs/specs/headline-radar.delta-sources.md` 第 8 节）：Reddit 官方接口（用户自己申请免费密钥）；
  GitHub 动态和版本发布；抓网页全文、AI 给热榜写摘要（V2）。X / Facebook / Threads / Quora / TikTok / 小红书不做（要登录或付费，抓取违反平台条款）
- 画像的差异化（2026-11-27 作者同意方向，排期等 V2 画像全量跑完再定）。原则：少让 AI 猜，多用程序算；建在 AI 平台给不了的三点上——跨平台、几年的完整历史、数据在用户手里。按优先级：
  1. 行为画像：只用时间戳在本机算，不发给 AI——几点聊天、考试周和假期的差别、一个项目持续聊了多久、话题首次出现 / 最集中 / 最后一次
  2. 变化轨迹：按月统计兴趣和关注点（本机向量模型），哪些一直在、哪些出现过又消失；每版画像自动对比上一版（多了、少了、被标「过时」的）
  3. 画像会预测、再用事实检验（如「你可能会放下 X」，一个月后查 X 还有没有出现），连同「不像我」的记录，让画像随时间被用户校准；属于 V2「闭环」
  4. 本机 MCP 服务：其他 AI 经用户同意查询 vault 和画像，替代手动复制「给 AI 的说明」
  5. 对话之外的来源：笔记、剪藏、简报评价（如说感兴趣但相关新闻从来不点开）
- 画像访谈个性化（2026-11-27 作者提出，规格在全量画像跑完后写）：追问轮次、用户选主题和禁区、跳过也当信号、内置「人生故事」框架
- 画像第 2 步抽样（每个月最多分析 N 个对话），对话很多时省钱（2026-11-27 讨论，作者这次选了全部跑）
