# ADR 0009：个人画像的实现决定

日期：2026-11-26　状态：已采纳
相关规格：`docs/specs/profile.md`、`docs/specs/vault-schema.delta-profile.md`

规格没写死、实现时定下的做法。

1. **分批**：第 2 步每次请求最多 1 万字材料（`extract.BATCH_CHARS`）。短对话拼在一起，长对话按段切开，单段超过 1 万字的按字数切。每个对话有编号 C1、C2……，AI 按编号回答，程序按编号找回对话。
2. **原话核对**：AI 给的原话和材料都先去掉空白和 Markdown 符号（与 `chat/source.py` 的 `normalize` 相同），再看是不是材料里某一段的子串。去掉符号后少于 2 个字的原话不算。一条观察至少要有一句来自「我写的」或笔记的原话；只引用了贴回的 AI 回答的观察丢掉（规格第 1 节：认同 AI 的话也要有自己表态的原话）。核对用整个对话的材料，所以跨切块的原话也找得到。
3. **缓存**：`.eia/eia.db` 新表 `profile_observations`（表结构版本 2，第一次迁移）。key 是材料全文、对话 id 和标题、提示词版本 `PROMPT_VERSION`、模型名的哈希。改提示词时把 `PROMPT_VERSION` 加一，旧缓存自然作废。每个对话做完就写一次，中途出错时已完成的不丢。`eia db rebuild` 会清掉缓存，下次全部重新发。
   - `tests/db/test_db.py` 的两个迁移测试原来写死「假装升到版本 2」，现在真实版本就是 2，改成「当前版本 + 1」，测的内容不变。
4. **汇总的量**：第 3 步每次最多发 6 万字的观察（`synth.SYNTH_CHARS`）。超过时保留最近的，画像里写明「最早的 N 条没有参与汇总」。只跑 3 个月时远达不到；以后跑全部对话时再看要不要改成分段汇总。
5. **「你可能没意识到的你」** 单独一次请求，发全部观察（带类别），结论一律当作推断。（已被第 10 条取代：现在是「01 心理」下的一个小节，和其他小节在同一次请求里写。）
6. **「不像我」的延续**：新画像末尾有一节「你说过不像你的」，把上一版勾了 `[x]` 的条目和上一版这一节里的条目都带过来。所以只读最新一份画像就够，否认过的不会因为隔了一版就失效；想撤回，删掉那一行。
7. **文件名**：`profile/<日期> 画像.md`，同一天再跑就是 `画像 2`、`画像 3`。日期按 vault 时区。
8. **提示词里称呼用户为「TA」**，不假定性别；画像正文用「你」。
9. **对话链接** 写成 `[[文件名|对话标题]]`。标题里的 `|`、`[[`、`]]` 换掉，免得破坏链接。

## 补充：细分章节（2026-11-26，docs/specs/profile.delta-format.md）

10. 第 3 步改成 4 次请求，每次的系统提示词（`prompts.py` 的 `PART_*`）只列这一次该写的小节 key；AI 写了别的小节（比如在第 1 次写了「教育」）程序直接丢掉，不挪到别处。03 兴趣用重复的 key `interest` 加 `title`，没有 title 的丢掉。
11. 第 4 条（汇总的量）照旧：前 3 次请求发同一份观察清单（每条只带一句原话，截到 60 字），超过 6 万字保留最近的。
12. 决策记录、时间线的要点按证据里最早的日期排序，行首写这个日期；AI 给的顺序不算。
13. 原 F18-04、F18-05 测试改为检查新结构（旧的四大类不再存在），检查的东西不变：没证据的进未解问题、对话数天数由程序算、文件有效带链接。
14. 第 2 步提示词没改，`PROMPT_VERSION` 不变，已有的观察缓存继续用。
