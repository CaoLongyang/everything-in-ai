# ADR 0010：插件同步用网站自己的接口

日期：2026-11-27　状态：已采纳（作者 2026-11-27 决定「走接口」）
相关：`docs/specs/chat-sync.md`、`docs/ROADMAP.md`「明确不做」

1. **为什么不读页面文字**。最初的规格读页面上显示的文字，但 ChatGPT、Claude 页面上不显示每条消息的时间，只能用「收到的时间」近似；长对话要往上滚才加载全；判断哪些对话更新过只能按侧边栏顺序猜。网页自己用的接口返回的数据和官方导出包一样，有每条消息的时间（`create_time` / `created_at`）和每个对话的更新时间（`update_time` / `updated_at`），一次取全。
2. **和「明确不做」那一条的关系**。原来写的是「模拟登录调用平台内部接口——封号与凭证泄露风险」。它要防的是把登录凭据拿到浏览器外面用（导出 cookie、在命令行里冒充浏览器登录），凭据一旦离开浏览器就可能泄露。这里的做法不同：请求在用户已经登录的网站网页里发，用的是网页已有的登录状态，和网页自己刷新一样；ChatGPT 需要的临时令牌只在那个网页里用，不存、不发给 eia、不出浏览器；只用取数据的接口。所以把那一条改写成「在浏览器外面使用登录凭据」，范围更准确，原来要防的风险照样防住。
3. **还剩的风险**。接口不公开、随时会变（失效时不写坏文件，见规格第 7 节）；OpenAI、Anthropic 的条款不鼓励自动取数据，被限速或账号受影响的可能不是零。缓解：每天一次、一次一个请求、对话之间隔 2 秒、遵守 429、一天被限 3 次就停。很多人在用的开源导出工具（chatgpt-exporter、claude-exporter）也走同样的接口，且请求更密。
4. **转换放在 eia 里**。插件只把网站返回的原始 JSON 发给本机的 eia，由 Python 转换：和官方导出包的解析共用规则、能用 pytest 测；网站改格式时只改 eia。
5. **参考的开源代码**：pionxzh/chatgpt-exporter（MIT，`src/api.ts`）、agoramachina/claude-exporter（MIT，`chrome/content.js`、`chrome/utils.js`）。只改写请求接口和走对话树的部分，写进 `THIRD_PARTY_NOTICES.md`。
6. **Gemini 不在这一版**：接口返回没有字段名的嵌套数组，难度和维护成本都高得多，先继续用现有的 Gemini 导出插件。
