# ADR 0001：frontmatter 的写回方式，以及命令行库的选择

日期：2026-11-16　状态：已采用（2026-11-20 作者 未提出异议）

## 背景

SPEC-vault-schema.md 写的是用 ruamel.yaml 的往返模式读写 frontmatter，用 typer 做命令行。
实现时这两点都改了。

## 决定

1. **不重新序列化 frontmatter，只替换被改动的字段所在的行。**
   读取用 PyYAML 解析；修改已有文件时，用 PyYAML 找出每个顶层字段在原文里的位置，
   只把要改的字段那几行换掉，新字段追加在末尾。写完再解析一遍，结果和预期不一致就拒绝写入。
2. **命令行用 click，不用 typer。**

## 原因

- spec 的要求是"读入再写出，diff 为空"。ruamel 的往返模式会保留键顺序和注释，
  但仍会规整缩进和部分引号，做不到逐字节不变。按行替换可以：没改的行完全不碰。
  这对 V0 很重要，因为你会在 Obsidian 里手动改这些文件。
- 写这段代码的环境装不了新的包，ruamel.yaml 和 typer 都没法在这里跑测试。
  交付没测过的代码违反 TEST-PLAN.md 第 4 节，所以选了能在这里完整测试的方案。
- typer 本身就是 click 的一层封装，直接用 click 少一个依赖，命令的用法完全一样。

## 代价

- 只能改顶层字段，不能只改嵌套结构里的某一项（要改就整个字段替换）。目前没有这种需求。
- 被替换的那个字段如果行尾带注释，注释会丢。其他字段的注释不受影响。
- `io.py` 多了约 60 行定位和替换的代码，对应测试是 F7-01、F7-03。

## 文件结构与 spec 的差异

`src/eia/schema/` 比 spec 多三个文件：`naming.py`（文件名规则）、`vault.py`（目录和配置）、
`create.py`（新建条目）。职责没有变，只是拆得更细。
