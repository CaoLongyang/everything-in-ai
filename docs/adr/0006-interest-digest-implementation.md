# ADR 0006：兴趣草稿与按兴趣过滤实现中的决定

日期：2026-11-21　状态：已采纳
相关：`docs/specs/interest-digest.md`

1. **按对话归组，不按单条消息。** 每个对话把「我」说的话（≥15 字）和笔记拼起来算一个向量。
   单条消息里大量是「那这个怎么改」这类接着上文的话，单看没有主题；按对话归组更稳，也直接得到证据（哪几个对话）。
2. **归组用球面 k-means，固定随机种子**（`kmeans`，k = min(最多兴趣数×2, 对话数÷4)），同样的输入得到同样的分组。
   小于 2 个对话或 5 条消息的组丢掉；多给文本模型 50% 的组，不成主题的由它标 `skip`。
   作者的真实数据（974 个对话）：本机归组约 3 分钟，30 组，人工看过组名大致成主题。
3. **第 1 步必须在本机做**：`llm.embed` 不在 127.0.0.1 / localhost 时直接拒绝（`Endpoint.is_local`），
   否则「只发少量摘录」的承诺就破了。
4. **草稿是 `interests/draft.md`（note 条目）**，勾选框就是选择；`accept` 用勾上的项**整份替换** `interests` 段。
   现有兴趣列在草稿最前面并勾着，所以重新生成不会丢掉已有兴趣。旧草稿备份到 `.eia/interests/draft.bak.md`。
5. **评价存 `interests/feedback.jsonl`**（vault 里，不在 `.eia/`）。和评价过的报道相似度 ≥ 0.85 视为同一类：
   不相关 → 排除，相关 / 4–5 星 → 加 0.05。`min_score` 0.55、0.85、0.05 都还没用真实评价校准。
6. 已经在前几天的今日兴趣里出现过的报道不再出现（`.eia/interests/shown.json`，保留 7 天）。
7. **修了两个已有的 bug**（都是这次写测试时发现的）：
   - `schema/io.py`：同一个时间对象写两次时 YAML 会写成 `&id001` / `*id001`，之后按行改字段会把文件弄坏。
     改成永远照写两遍。真实 vault 检查过：0 个文件受影响（导入时恰好是两个不同对象）。
   - `schema/configedit.py`（从试用页面挪进来）：`key:` 下面顶格写的 `- 列表项` 没被当成这一段，替换后旧项残留。
8. 从 Horizon 复制 / 改写的三处代码见 `THIRD_PARTY_NOTICES.md`；新闻雷达也用上了链接规范化（BBC 的 `?at_medium=RSS`）。
