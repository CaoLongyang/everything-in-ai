# ADR 0007：SQLite 数据库实现中的决定

日期：2026-11-21　状态：已采纳
相关：`SPEC-storage.md`

1. **对外的函数签名不变**（`load_items`、`save_items`、`load_vectors`、`save_vectors`、`read_feedback`、`rate`、`read_runs`），
   只把里面的读写换成数据库。所以 F11–F13 的测试几乎不用改；改的只是那几条直接检查旧文件位置的断言。
2. **预览（--dry-run）不写任何文件**：数据库存在就以只读方式打开；不存在就用内存数据库，并把旧版本的散文件读进来
   （不移动），保证预览和真跑看到同样的数据。
3. **索引在需要时增量更新**（`db.index.sync`：比较修改时间和大小）。规格里说的「eia 写 Markdown 时顺手更新」没有做：
   增量检查本身就够快（作者 vault 988 个文件，没变时 1.4 秒），多一处更新只是多一处出错的地方。
   第一次建索引 43 秒（全文索引把所有正文写进去）。
4. **全文搜索**用 FTS5 trigram：3 个字及以上 `MATCH`；1–2 个字（「汽车」「AI」）在全文表上 `LIKE` 逐条比对，结果按更新时间排序，片段自己截。
5. **向量用 `array('f')` 存 float32**，不依赖 numpy（数据库层在没装 `[news]` 时也要能用）。精度从 float64 降到 float32，对余弦相似度没有可见影响。
6. 评价每次写入后把整张 `feedback` 表导出到 `interests/feedback.jsonl`（几百条，整份重写比增量追加简单可靠）。
7. 打开数据库到一半失败（版本太新、迁移出错）时立刻关闭连接（测试时发现的连接泄漏）。
8. `entries` 表比规格多一列 `message_count`，网站的对话列表要显示消息数。表结构还没发布，直接写进版本 1。
9. 也把 frontmatter 解析换成 libyaml 的 C 版本（结果与 SafeLoader 一致），所有读文件的地方都快了几倍。
10. 迁移实测（2026-11-21，作者真实 vault）：报道 344、向量 1,082（270 + 812，与旧文件逐个核对一致）、运行记录 2；
    数据库 55.7 MB；旧文件在 `.eia/old/`（约 24 MB，确认没问题后可以删掉）。
